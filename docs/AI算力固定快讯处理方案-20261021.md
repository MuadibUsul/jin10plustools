# AI算力CPI与AI景气度指标处理方案

本方案依据两份用户工作簿、当前 PLUS 项目代码及 Silicon Data 官方产品/API 文档制定。原工作簿未修改。本阶段为方案交付，未开发栏目、未访问生产服务器、未部署。

## 1. 交付目标

新增两个独立固定快讯栏目：AI算力CPI（Token支出价格指数）与AI景气度指标（GPU租赁价格）。复用现有取数、任务、图表、规则文案、Skill润色、人工确认、版本、下载与数据导出机制，使现有七类增加到九类。

可靠性的定义是：每个数字能追溯来源；相同快照能重放相同产品；没有新数据时不出假新稿；缺失和修订有明确处理；AI不能创造价格、涨跌幅、极值或因果判断。

## 3. 数据源与口径

Token锁定Silicon Data LLM Token Expenditure Index，Bloomberg代码SDLLMTK；单位USD/million tokens。它是使用量加权的市场有效支出价格，受到模型定价、使用结构和成分变化共同影响。不得自行对OpenAI、Anthropic、DeepSeek价格做算术平均并冒称同一指数，也不能仅凭指数下跌断言模型厂商当周降价。

GPU锁定SDA100RT、SDH100RT、SDB200RT及相应NeoCloud口径。官方API有neo/hs之分，H100/A100大型云厂商价格另成系列。首次接入必须用多日重叠数据对齐样本，确认系列、币种、单位和版本后才能续接；无法对齐时保留两条独立序列，禁止硬拼。

官方API需订阅和产品权限；本次未假定用户已有该权限，也未申请或购买。公开页能展示指数，不代表免费提供完整、稳定、可机读的历史和日值。本次只读试取公开Token仪表盘接口，业务响应为401未认证，证明不能直接宣称免费全自动已可行。

接入顺序：

1. 有现成授权时，使用官方API/CSV或同口径授权分发源，验证最新日、精度、历史修订和访问范围。
2. 尚无机读权限时，先用现有工作簿完成历史导入、回放和全流程验证；设置可审查的CSV/Excel更新入口。日常只需补一条Token或一组三卡数据，其余流程全自动。
3. 公开页面只作交叉核对；只有返回明确日期、系列、单位和真实精度的结构化数据且稳定验证通过后，才可启用自动采集。不能抓网页第一个美元数或目测曲线后伪造四位小数。
4. 彭博等备用通道按现有权限使用。数据订阅、公开引用、再分发权限分别核对，不在没有权限时自动购买或绕过访问限制。

## 4. 数据治理与校验

原始工作簿和每次源响应保存文件摘要、采集时间及完整原始快照。规范化记录保存团队、指标代码、系列版本、数据日期、原始数值、单位、来源、精度、获取方式、修订号和原始快照引用。

工作簿导入先预检再提交：忽略全空价格行和旁边演算区；保留缺失；重复同日同值去重；重复异值进入差异清单；日期/单位/系列不明不能成为正式序列。既有人工表作为带来源标签的历史基线，不自动升级为“官方已验证”。

官方校准或新文件导入产生新修订，保留旧值与差异理由。已经确认的稿件绑定当时的数据快照，历史校准不静默改稿；编辑可在新版本中采用修订。来源改变、方法改变和历史修订均使相关缓存失效。

采用Decimal计算，保存源精度。Token按官方四位小数读取/展示；GPU按官方两位小数；周变化保留两位百分数。低精度输入不能自动扩展成高精度事实。原始值、展示值和计算值分开。

异常值不是自动删掉：识别日期倒序/跳日、非正数、API缺值标志（-1等）、系列切换、量级突变、历史成片改写。结构或单位错误阻断；可能真实的大幅变化保留并显示待核对，核对后允许采用，避免把真实行情过滤掉。

## 5. 计算与措辞规则

两个栏目均包含周末历史，不沿用现有A股“前一工作日”的通用函数。按数据源发布的日期入库，稿件日期与数据截至日分别保存。工作簿最上方的预填日期、采集时间都不是数据日。

周变化固定为(P(t)/P(t-7自然日)-1)×100%。基准日没有真实值时不补前值、不拿七行前替代；该指标本期不报周变化并显示具体缺日。

GPU正文使用同一数据日的三卡价格。最新日缺一项时，只有在最新共同完整日仍是新数据且符合时效规则时才可采用该共同日，并明确标注截至日；否则等待更新，不混合三张卡的不同日期。单项缺失时不能生成完整三卡“代际分化”结论。

所有叙述先由规则计算事实：当前值、七日变化、近7/30/90日区间、滚动六个日历月高低、已收录历史峰值及发生日。高于此前峰值才是新高；等于则是并列；低于则仅描述距峰值差距。半年按日历月计算，不按180行计算。

任何窗口存在未补齐的缺日、估读值或未核实段落时，不输出绝对“历史/半年新高”；采用“已收录数据中”并显示覆盖区间，或省略该判断。不能把B200的短历史说成整个GPU市场的历史。

第一版优先使用可直接验证的措辞（周涨/跌、区间、差距）。横盘、低位、波动收窄、持续反弹等表述须先规定窗口、阈值与比较期，经历史回放验证后启用；规则和阈值在团队配置中可见、可修改并留版本。它们不交给AI自由判断。

Token的“AI算力CPI”保留为栏目名，但固定说明明确其为Token支出价格基准，不等同固定质量/固定篮子的传统CPI。GPU只报告A100/H100/B200三卡范围；不因只看三卡而自动断言覆盖所有最新代际。

## 6. 图文产品

Token成品图：统一品牌折线图，主图保留长期趋势，附最近30日局部趋势，标注最新价格和七日变化。单位明确美元/百万Token；纵轴不使用对数或无说明截断制造走势印象。

GPU成品图：同一时间轴三条价格线，保留价格真实单位，图例/线条直接对应卡名，并列当前价格与周变化。较短的B200只从真实起始日绘制。默认一张图完成，避免把无关的第二指标或人为合成“景气分数”放入产品。

图表读取同一事实快照，禁止Excel图表缓存与正文用不同数据。保留可调整的观察窗口、原始历史导出与来源核对。最终图片遵循项目既有image_delivery：原PLUS水印、等比缩放、266000字节上限、清晰度检查及既有日期/标题MD5命名。

正文结构沿用用户样稿：标题、动态事实段、分隔线、三条可编辑固定说明。默认说明放正文末尾，后续若有明确要求再调整到图中。

固定说明建议修订为稳健口径：Token区分定价效应与使用结构效应，产业影响写成条件性解释，不把指数变化直接当作个别公司的定价权证据；数据来源标明Silicon Data及实际指标口径，成分厂商举例仅在当期可验证时保留。GPU说明其为标准化租赁基准，价格受供需、租赁结构等共同影响，代际比较不是性能价格比结论。

AI读取经校验的事实表、两项新文字Skill和团队固定说明，仅润色允许表达；不能改动数字、单位、日期、比较窗口、来源或新高/并列状态。扩展现有数字守卫到单位、日期和事实标签。AI失败回退完整规则稿，数据失败则等待数据，不能用AI填补。

### 6.1 两项独立文字 Skill

两项Skill是必交付项，沿用项目现有固定快讯文字Skill资产及自动生产机制。所有有效生成任务必须经过对应Skill阶段，记录所用版本、团队规范版本、AI模型与执行结果。AI不可用时仍使用该栏目的规则稿回退，并明确记录回退状态。

| 栏目 | Skill资产名 | 核心编辑规范 |
| --- | --- | --- |
| AI算力CPI | `jin10-plus-token-cost-text` | 明确美元/百万Token及截至日，描述七自然日变化与已验证的区间/趋势；区分模型降价、使用结构与成分效应，不能从指数单独认定当期原因。 |
| AI景气度指标 | `jin10-plus-gpu-rental-text` | 三卡同一截至日、NeoCloud口径、美元/GPU/小时；保留各卡周变化，正确表达新高/并列/距峰值差距；仅在已验证事实满足规则时描述三卡分化。 |

每项资产包含：

- `SKILL.md`：栏目适用范围、必需事实、标题优先级、正文结构、单位和日期表达、允许结论与禁用推断、缺失处理、固定说明边界。
- `references/history.md`：真实参考文案。现有材料每类只有一条样稿，须附本次校正说明并经过审核后纳入；不伪造20条历史样本。以后积累已确认版本，只作风格参考，历史数字不作为当期事实。
- 栏目输入规范及运行时manifest：定义必需字段、字段单位、缺失值规则、事实标签和版本摘要，并登记到现有Skill库；开发时与现有manifest协议保持一致。

输入不是整张Excel或未经处理的网页，而是同一期的事实包：数据日、价格/精度、周基准日及价格、周变化、极值及发生日、窗口完整性、来源口径/版本、已核准趋势标签、完整规则标题/正文，以及团队配置版本。

输出遵循现有生产适配器的`title/body`契约。固定三条说明由团队配置独立保存并在交付阶段拼接，Skill不重写它们。标题的主旨必须取自规则已确认的事实优先级，不允许AI为了吸引注意新增“创新高”“全面紧缺”等结论。

结果验收不能只比较数字集合：还要核对数字与指标的对应关系、卡名、单位、涨跌方向、日期与比较窗口、极值状态。即使数字完全相同，把B200价格写给H100、把下跌改上涨、把并列写创新高，也必须拒绝并回退。

Skill库新增两张卡片，支持沿用现有权限管理团队规范、开关和修订。资产及样本必须随生产镜像一起打包，不依赖开发电脑上是否安装Codex或个人Skill。两项Skill、规则/模板版本及相关数据快照摘要均参与产品缓存判断。

## 7. 接入现有项目

注册token_cost/gpu_rental两个栏目与取数适配器，增设各自的源日期策略。调度沿用当前工作日早间稿件生产习惯，采集与历史维护覆盖源提供的周末记录；没有新数据时显示等待并避免重复新建同一产品。首次用真实更新记录确认源时区、发布时间与延迟，再确定时效阈值。

补齐当前写死五类的Skill、动态模板、变量白名单、默认注释、Skill卡片、设置页和类别简称；新增后七类变九类。快照文件、缓存数据摘要、重绘分支、过程核对页同步接入，确保只用快照重绘无需联网。

新建团队隔离的结构化观察值及修订记录，注册到数据库导出。用户可导出：

- Token：日期、支出价格（美元/百万Token）、七日基准日期/价格、周变化、来源、精度/核验状态、修订号。
- GPU：日期、A100/H100/B200价格、各自周变化、系列口径、缺失标记、来源及修订号。

默认业务导出保留易读宽表；来源修订提供独立明细，导出不包含密码、密钥或原始来源二进制。

## 8. 实施顺序与验收

阶段一：完成工作簿审计和指标口径表，导入历史候选数据，生成缺失/精度/系列差异报告。验收包括两份工作簿原件不变，以及本方案列出的价格、周变化和并列高位能够复算。

阶段二：用历史回放完成计算、两张成品图、规则正文和固定说明，逐个查看上涨、下跌、持平、并列高点、缺日、空行、单卡缺值、历史修订等日期，审核标题是否有事实依据。

阶段三：接入取数或授权文件更新入口，交付两项Skill资产、真实样本与校正说明、manifest/事实映射、Skill库卡片及版本记录；补齐模板/设置/任务/归档/导出，验证断网、API权限不足、-1、源停更和AI失败行为。只有机读源验证成功才启用对应全自动取数。

阶段四：完整回归原七类，新增栏目默认关闭；生产先核对PLUS项目与正在使用的镜像/数据库，备份后仅迁移和更新PLUS API/brief-worker。共享反向代理、其他项目与数据库卷不改。先预览核对，再启用新栏目的排期。

最终验收：每期标题/正文/图表数字一致；所有数值与比较都可追到快照；确定性回放通过；团队隔离通过；历史校准不改已确认稿；来源未更新不冒充新数据；两项Skill在生产任务中确实执行且版本可追溯，数字未变但指标归属/方向/极值结论被改动的错误也能拦截；九类设置/生成/确认/下载/导出均可用。不能以“抓到了网页数字”作为上线完成。
