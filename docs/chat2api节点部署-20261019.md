## 访问

- 域名入口（2026-10-19 接入 Caddy，已实测 200）：
  - Token 池管理：登录工作台后进入 **设置 → chat2api**（仅管理员），不再公开裸页面。 `__Secure-next-auth.session-token.0/.1` 是同一个加密会话 Cookie 因超长被拆成的两段，不是两个 Token，也不能用于 chat2api 刷新；设置页会拒绝这类 Cookie 并提示改用 accessToken。输入框可直接粘贴 `/api/auth/session` 的整段 JSON 或 Cookie 行，后端会自动提取 accessToken/refreshToken（加密的 sessionToken 会被忽略）；页面内也附了在 chatgpt.com Console 一键复制 accessToken 的命令。
  - OpenAI Base URL（含 `/v1`）：`https://plus.tlines.tech/<API_PREFIX>/v1`
  - OpenAI Base URL（渠道配置用，不含 `/v1`）：`https://plus.tlines.tech/<API_PREFIX>`
- 直连入口已按用户要求关闭：容器端口只绑 `127.0.0.1:5005`，公网仅域名可用；Caddy 对 `/<API_PREFIX>/tokens*` 与 `seed_tokens*` 返回 404，Token 管理只走登录后的设置页。
- 模式 A：使用 `.env` 的 `AUTHORIZATION`（`sk-c2a-...`），请求走号池。
- 模式 B：直接填网页端提取的 AccessToken（`eyJ...`）透传。
- 注意：`/v1/models` 未实现（404），客户端探测模型列表时可能告警；`/v1/chat/completions` 正常。

## 运维（`/opt/chat2api/manage.sh`）

- `./manage.sh status`：容器状态、宿主机出口 IP/国家、最近日志。
- `./manage.sh rotate-ip`：WARP 已按宿主机原生 IP 要求移除，出口 IP 固定；该命令只重启 chat2api 并打印当前出口。
- `./manage.sh add-token <AccessToken/RefreshToken>`：追加到 `data/token.txt` 并重启 chat2api（文件由容器以 root 创建，脚本通过 `sudo -n tee -a` 追加）。
- `./manage.sh test <KEY>`：向本机 `/v1/chat/completions` 发一次 `gpt-4o-mini` 的 “Reply OK” 请求。
