# chat2api OpenAI 兼容节点（2026-10-19）

## 目标

把 ChatGPT 网页端凭证转换为标准 OpenAI API 节点，供后续 Plus新鲜事、Plus注解辅助等栏目调用 `/v1/chat/completions`。

## 部署

- 服务器：`104.207.82.85`，目录 `/opt/chat2api`（`deploy` 用户拥有）。
- 编排：`/opt/chat2api/docker-compose.yml`，只运行 `lanqian528/chat2api:latest`，端口 `5005:5005`，数据卷 `./data:/app/data`。
- 按用户 2026-10-19 的补充要求：**不部署 WARP**，`.env` 中不设置 `PROXY_URL`，chat2api 直接使用宿主机原生 IP 出站（Cloudflare trace：`ip=104.207.82.85`、`loc=US`）。
- 密钥与随机路径前缀只存在于 `/opt/chat2api/.env`（权限 600），不写入仓库：`PORT`、`API_PREFIX`、`AUTHORIZATION`。
- 其余参数保持：`HISTORY_DISABLED=true`、`ENABLE_LIMIT=true`、`SCHEDULED_REFRESH=true`、`RANDOM_TOKEN=true`、`RETRY_TIMES=3`、`UPLOAD_BY_URL=true`、`ENABLE_GATEWAY=false`。

## 访问

- Token 池管理页：`http://<服务器IP>:<PORT>/<API_PREFIX>/tokens`
- OpenAI Base URL（含 `/v1`）：`http://<服务器IP>:<PORT>/<API_PREFIX>/v1`
- OpenAI Base URL（渠道配置用，不含 `/v1`）：`http://<服务器IP>:<PORT>/<API_PREFIX>`
- 模式 A：使用 `.env` 的 `AUTHORIZATION`（`sk-c2a-...`），请求走号池。
- 模式 B：直接填网页端提取的 AccessToken（`eyJ...`）透传。
- 注意：`/v1/models` 未实现（404），客户端探测模型列表时可能告警；`/v1/chat/completions` 正常。

## 运维（`/opt/chat2api/manage.sh`）

- `./manage.sh status`：容器状态、宿主机出口 IP/国家、最近日志。
- `./manage.sh rotate-ip`：WARP 已按宿主机原生 IP 要求移除，出口 IP 固定；该命令只重启 chat2api 并打印当前出口。
- `./manage.sh add-token <AccessToken/RefreshToken>`：追加到 `data/token.txt` 并重启 chat2api（文件由容器以 root 创建，脚本通过 `sudo -n tee -a` 追加）。
- `./manage.sh test <KEY>`：向本机 `/v1/chat/completions` 发一次 `gpt-4o-mini` 的 “Reply OK” 请求。

## 验证

- 容器启动无异常，Uvicorn 监听 `0.0.0.0:5005`；token 管理页返回 200。
- 服务器本机与外网各发一次 `gpt-4o-mini` 请求，均返回 HTTP 200 与 `"content":"OK"`。
- 号池当前为空：日志显示 `Request token is empty, use no-auth 3.5`，即无凭证时会走匿名降级；正式使用前应在管理页粘贴自己的 AccessToken/RefreshToken。
- 安全提示：管理页目前仅由随机 `API_PREFIX` 保护，没有额外登录；不要把该地址外传。若需要，可再加一层 Basic Auth 或仅绑定内网。
