# 提示词 0：总控 Agent（建议首先执行）

你是资深软件架构师、Python/浏览器扩展工程师、数据库迁移工程师及财经编辑系统架构师。你负责对本地已检出的 `MuadibUsul/jin10plustools` 仓库进行**最小侵入、兼容优先、可回滚**的增量开发，加入 News Skill OS 能力。你的第一优先级不是增加功能，而是确保现有业务不退化。

## 不可妥协的原则

1. 首先完整审计实际仓库：`jin10-server/`、`jin10-extension/`、`deploy/`、Docker Compose、环境变量、数据库迁移、认证、API、测试、构建与发布流程。禁止根据目录名推断代码行为。
2. 不删除、替换或大规模重构现有业务模块；不变更原有 API 的路径、HTTP 方法、请求响应格式、认证语义、返回码；如确有必要，提出兼容适配方案，未经批准不得修改。
3. 不改变浏览器扩展现有 manifest、权限、消息协议、页面交互和已使用的存储键；新增入口必须可选、默认关闭。
4. 不更改或清空已有数据库表和持久卷；数据库迁移只能默认向后兼容、可重复执行，必须说明回滚方案。绝不执行 destructive migration。
5. 不修改现有 `.env` 密钥，不将密钥写入源码、日志或测试；新增环境变量必须是**可选且有安全默认值**。
6. 新能力必须使用特性开关，默认 `NEWS_SKILL_OS_ENABLED=false`；关闭时不触发任务、不写入新业务数据，既有业务执行路径不变。
7. 不调用真实付费 LLM、外部新闻 API 或 CMS 发布接口完成测试；通过 mock/stub/fixture 测试。未明确授权不对外发送数据。
8. 不自动发布新闻。人工审核是发布前强制门禁；MVP 只生成草稿和证据审查结果。
9. 开工前记录基线 commit、工作区状态、现有测试结果；独立功能分支开发，提交小而可回滚的 commit。
10. 出现未知架构、核心测试失败、数据库兼容性疑问或与现有业务冲突时，停止相关代码改动，输出具体阻塞及替代方案；不以臆测绕过。

## 目标能力

将新闻生产解耦为：新闻输入→事件识别→事实断言提取→来源/数字核验→背景挖掘→前因/后果/补充说明→草稿生成→质量审核→人工审批。建立三种底层契约：

- `Skill Manifest`：独立 Skill 的版本、输入输出 Schema、权限、运行配置和评测；
- `NewsEvent / Claim / Evidence`：事件、原子事实、证据、来源归属与分析结果；
- `Workflow DAG`：显式依赖、状态持久化、重试、幂等、可观测性与局部重跑。

## 执行顺序（每步均须交付）

A. **只读审计**：输出真实文件路径与关键符号、架构图、现有业务依赖图、兼容性清单、风险登记册，明确哪些尚未证实。此步骤不得改业务代码。

B. **基线验证**：检查实际存在的测试、lint、构建、Docker 配置；记录能运行与不能运行的命令及结果。不能运行的测试不能宣称通过。

C. **架构适配**：提出两种实现方案，优先选择依赖更少、改动更少、对现有业务隔离更强的一种。写明新增文件、需改动的旧文件及每处原因；不得臆造仓库的目录和技术栈。

D. **协议实现**：先实现 Manifest/Schema 静态校验器、领域模型与纯内存或隔离存储版本的 DAG 执行器，不先接生产业务流。

E. **五个 MVP Skill**：事件提取、事实核查、背景挖掘、深度注解、质量审核。注意深度注解支持“前因/后果/补充说明”，写作可作为独立可替换节点；所有技能先用确定性 fixtures 验证。

F. **可选集成**：新增隔离路由/服务入口及开关；仅在既有认证、权限和错误处理规范下接入。不得影响旧扩展、旧 API、旧数据库。

G. **回归和安全**：运行原测试、增量测试、Schema 合同测试、开关关闭测试、权限测试、数据库迁移测试、任务幂等和并发测试。最终输出准确的 pass/fail/blocked 结果。

## 最终交付格式

1. 现有系统审计报告（具体路径、函数、调用链、风险）。
2. 变更清单（新增/修改文件、原因、影响范围）。
3. 设计决策记录（ADR）与三类协议规范。
4. 可运行的 MVP 代码与说明（前提是环境允许）。
5. 测试证据和业务兼容性矩阵。
6. 回滚说明，包含关闭开关和代码/数据库层回滚。
7. 尚未解决的风险、下一阶段建议。

禁止使用“已兼容”“已验证”“已部署”等未经实际执行证明的表述。

# 提示词 4：NewsEvent / Claim / Evidence 领域模型

为新闻事件建立结构化且可追溯的数据模型，支持以下实体：`NewsEvent`、`Source`、`Evidence`、`Claim`、`ClaimEvidenceLink`、`Analysis`、`Draft`、`ArtifactRevision`、`AuditEvent`。

设计要求：

- Claim 是可独立核验的原子断言；数值必须区分金额、币种、比例、单位、同比/环比、实际/预测、财年/自然年、时间范围和报道归属；
- 事实状态：`unverified`、`corroborated`、`verified`、`disputed`、`rejected`、`superseded`；状态升级必须有可解释规则与审计记录；
- 两个媒体转载同一来源不能算作两份独立证据；存储原始来源和转载链；
- Analysis 必须声明依赖的 Claim 和 Evidence，不得把推断伪装成事实；
- 采用不可变 revision 或追加式变更历史，旧文章能够重建当时采用的事实快照；
- 数据库写入使用事务、唯一键、外键/约束及必要索引；
- 不新增与现有业务表冲突的名称；不修改旧表、不执行删除或清空；
- 提供纯 Schema 版及适配当前仓库数据库框架的持久化版（先经评审）。

实现测试至少覆盖：口径冲突、来源重复、断言撤回、事实修订、历史回溯、并发版本冲突、跨事件隔离。

# 提示词 5：Workflow DAG 执行引擎

实现独立、最小可用的 `news.workflow/v1` DAG 执行引擎。工作流以 YAML/JSON 定义节点、Skill 版本、输入绑定、依赖、超时、重试与人工审核门禁。先支持 `queued/running/succeeded/failed/blocked/cancelled`，并对重试次数及状态转移做严格约束。

核心约束：

- 注册时检查环、缺失节点、输入路径和 Schema 类型；
- 节点运行必须记录 `run_id`、`node_id`、`skill_version`、输入摘要、输出摘要、来源快照、时长与错误；
- 节点执行需要幂等键；对外部有副作用的工具不做盲目自动重试；
- 对失败节点支持重试和隔离，不能影响既有主业务；
- 不执行全局后台扫描或增加默认常驻 worker；
- 保留局部重跑接口：可由改动的 Claim ID/字段反查依赖节点，仅使必要缓存失效；
- 人工审核必须阻断发布节点；MVP 没有自动发布节点；
- 使用无网络 fixture 运行测试，证明同一输入的确定性节点可缓存复用。

交付独立运行样例 `source → extraction → verification → [background, causal_analysis] → writing → review` 和单元/集成测试。不得假设因果分析总能和背景研究并行，必须按真实输入依赖决定。

# 提示词 6：财经深度注解 Skill

实现 `finance.causal-analysis`，把既有编辑规范形式化为可调用能力。**固定输出三段：前因 / 后果 / 补充说明**，目标是挖掘具体事件的深度和隐藏信息，而不是重复快讯。

输入：NewsEvent、已核实 Claim、Evidence、背景材料、选题限定、历史数据与时间基准。输出：三段正文、关键新增信息、每项分析对应的 Claim/Evidence ID、事实与推断标签、未解决问题和置信说明。

编辑约束：

1. 先研究这次新闻相较既有信息有什么变化，查关键时间表、金额、合同结构、供应链瓶颈、利益相关方、成本承担者、产业及金融传导。
2. 区分“已确认事实”“媒体援引”“机构预测”“模型/编辑推断”。
3. 重大数值核对币种、单位、统计期、同比环比和比较基准；缺少可信证据则保留不确定性，不能编造来源。
4. 不以股价同步变动反推事件因果；不把相关性写成因果性；不进行无依据受益股罗列。
5. 没有额外高价值信息时应明确说明，而不是强行扩写。
6. 默认不对外发布、不自动访问付费数据或消耗高额研究预算；检索由工作流权限控制。
7. 如果上游只有“据知情人士”消息，后续不得提升为公司官方确认。

建立至少20个离线用例，覆盖融资、财报、央行政策、就业数据、能源物流、AI供应链、传闻纠错。提供可阅读的 rubric，检测增量信息、因果误判、数字错误、来源幻觉和三段格式。

# 提示词 7：五个最小 Skill 串联验证

# 推荐的实际使用顺序

首先将「提示词0」交给编码 Agent，并只允许执行 A/B 阶段；拿到真实仓库审计和基线结果后，再依次执行「提示词2—5」。之后用「提示词6—7」跑通业务闭环，最后交给另一个审查 Agent 执行「提示词8—9」。**不要一次性授权 Agent 在生产环境落地全部功能。**

## 第一阶段完成的定义（Definition of Done）

- 明确仓库真实架构和现有业务关键路径；
- 三项协议均有机器可验证的 Schema 与测试；
- 端到端研究型快讯样例在离线环境能跑通；
- 关键事实有证据链和版本历史；
- 事实修正可以触发最小范围局部重跑；
