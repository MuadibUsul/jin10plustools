## 运行方式

事实适配器先校验结构化事实，形成不可拆改的事实句，再按场景从版本化表达模块中组合标题、开头、比较与收尾。模型只能选模块 ID，不能另写数字、日期、单位或解释。没有合适场景、事实不全、资产损坏或无法校验时，保留完整旧稿；任务不因风格候选失败而中断。

`app/briefs/editorial_suite.py` 统一入口；`editorial_cn.py`、`editorial_market.py` 分别负责栏目事实；GPU继续使用已完成的独立适配器。US两栏风格包在 `app/briefs/editorial_packs/`，其他栏目在对应 Skill 的 `production/style-pack.json`。原始语料与历史档案没有改写。素材来源及哈希保留在风格包中；US两栏以现有规则与资料为依据，尚不冒充编辑签发范文。

候选记录包含场景、模块计划与快照、风格包版本/哈希、事实哈希、校验结果及模型选择状态，沿用现有 BriefVersion JSON 和导出流程，不新建表。事实修订会进入候选哈希。任务缓存签名纳入全部风格包；不使用仅按日期命中的新缓存。

团队自定义正文模板、关闭的 Skill 和自定义 Skill 指令优先，候选流程会跳过，避免覆盖团队设置。图片、注释、有效性、告警、任务及素材归档仍由既有流程处理。除为流动性和美股结构补充少量事实证据外，原计算与图表路径不变。

## 配置、切换与回退

`PLUS_BRIEFS_EDITORIAL_MODE` 可为 `off`、`shadow`、`active`，默认 `shadow`，已在配置、环境示例及两套 Compose 的 API/worker 中贯通。

GPU保留原有 `PLUS_BRIEFS_GPU_EDITORIAL_MODE`。无显式函数参数时，任一配置为 `off` 就关闭 GPU 候选；否则任一为 `active` 即请求启用，两者均为 `shadow` 时只记录候选。显式函数参数供定向调用和测试使用。

`active` 也不能跳过风格审核：包必须为 `approved`，且含 `review.approved_by`、`review.reviewed_at`。未审核包自动降为 shadow。通过审核后，选模块仍沿用团队已有 DeepSeek/chat2api/OpenAI 配置与实际模型追踪；模型不可用则使用受约束的完整确定性组合。不另建模型配置。

回退到 `shadow` 或 `off` 后重新生成后续稿件即可；不删除历史版本，不覆盖已确认稿。代码提交与推送以 Git 记录为准；本次未部署，未触碰生产服务器、凭据、数据库或发布入口。

## 回放与人工验收

在 `jin10-server` 下运行：

```powershell
..\.venv-news\Scripts\python.exe tools\evaluate_editorial_suite.py --out E:\daylycontents\outputs\fixed-editorial-new-review
```

输出目录必须不存在。可用 `--cases` 输入同结构的已存事实，`--seed` 固定匿名顺序，`--reviews` 导入人工评分并另建结果目录。工具不联网、不调用模型、不读写数据库或发布，不修改风格包审核状态。

`blind-review.md/json` 为匿名对照和待填评分；`review-key.json` 单独记录新旧映射；`evaluation.json` 按栏目记录有效候选、预期拒绝、错误接收、意外拒绝和独立断言。人工导入会核对包哈希与逐稿内容，防止把旧稿评分套到修改后的稿件。可直接采用率仅统计实际已评分项；没有评分时保持空值。

最终输出位于 `E:\daylycontents\outputs\fixed-editorial-review-20261030\final\`：

- `review/`：每个固定栏目各一组匿名A/B，共9组，全部为合成工程数据。
- `validation/`：45个合成工程场景，32个有效候选、13个预期拒绝，无错误接收、意外拒绝或断言失败。
- `archived/`：6份本地存档回放，其中原油ETF、换手率、股债性价比及GPU可形成4组对照；旧流动性非目标收盘、旧成交额缺结构化事实，两项保留旧稿。存档有文件哈希，未重新核验网站或当前行情。
