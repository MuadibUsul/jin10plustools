# 固定快讯生产整改与值班操作

本轮以 `eadb014` 为基础。程序故障优先排查，按原始响应 → 解析结果 → 数据库修订 → 工作历史 → 日期缓存 → 成稿逐层定位。缺少归因证据时保留“采集或解析未完成”“必要记录缺失”，不能据此宣布上游停更。

## 已实现的基础修复

- 快讯任务接口增加兼容字段 `failure`，包含错误码、原始失败消息、来源、缺失日期、最近数据日、可重试性与处理动作。原有 `error` 和任务状态继续可用。诊断绑定团队和任务，并核对当前错误，避免误用上次重试的错误文件。
- 必需交易日校验提供具体缺失日期。成交额原始响应含目标日期但无法解析成完整明细时，报告采集契约错误。未经原始响应核查的缺数不会自动归为“等待上游”。
- 美股晴雨表三个序列独立采集。一个序列失败时仍归档另外两个成功序列，原始数值响应及 HTTP 日期、缓存 Age、内容摘要一起归档。访客令牌响应和请求鉴权头不进入归档。ERP 和巴菲特指数分别指出缺少的目标日或前一交易日。
- HTTP 临时失败限次重试，成交额分页遵守总读取预算。意外任务异常成为可见失败并释放活动键，租约恢复连续中断六次后停止并报告。数据库不可用时继续保留租约作为恢复边界。
- worker 每分钟记录业务告警及恢复，状态文件跨重启去重。健康巡检失败独立记错，不阻止队列调度。现有登录后健康接口展示业务故障，容器探针检查 150 秒心跳。
- 发布使用服务器文件锁保护本地和 Actions 两种入口。发布镜像在复制本次代码前清除旧应用目录，防止被删除的模块残留。worker 发布时合并专用健康检查覆盖文件。

## 检查与恢复

在既有生产服务器 `/home/deploy/plus` 执行下列只读检查。

```bash
docker exec plus-api python -m app.services.production_health
docker exec plus-api python -m app.services.production_health --worker
docker compose logs --since 30m brief-worker
docker compose ps
```

完整业务检查遇到告警返回非零，心跳检查仅反映处理进程。业务报告可能同时有日历预警和出稿错误，应逐项查看。自动记录位于业务持久卷 `.brief-production-alerts.json`，错误详情在各团队的 `briefs/runs/<任务编号>/error.json`，美股来源失败列表为 `source-failures.json`，数值响应为 `us-source-*`。原始归档同时由既有工作流写入 PostgreSQL。

发生缺数时先查任务编号对应的原始响应与解析前后日期。原始响应有数而数据库无数，追查解析、事务与方法匹配。数据库有数而工作文件无数，核查历史恢复。工作文件有数而成稿无数，核查目标交易日、缓存签名与规则。原始响应缺数仍应继续查既有归档及同口径来源，保留调查范围与结论限制。

修复后通过编辑端对所需日期重新生成并核对。重绘仍使用所选稿件的不可变快照。确认和下载显式绑定版号。对于已有人工稿，重试前先核对当前版本。

发布继续使用 `deploy/deploy.sh` 或现有 Deploy PLUS 工作流。服务器新增的 `brief-worker-health.yml` 只配置 worker 探针。以后若手动重建 worker，应同时传入 `-f docker-compose.yml -f brief-worker-health.yml`。源配置、环境文件、数据库和存储卷沿用既有部署。容器 unhealthy 提供故障信号，Docker 自身不会因为该状态自动重启容器。进程退出由既有 restart 策略恢复，执行超时和租约机制负责任务恢复。

- 2026-11-24 核对生产数据库与工作历史，成交额有 11 月 19 日和 23 日，缺少 20 日。检查最近 80 条第一页原始归档，去重后 29 份，未发现 20 日。实时第一页也无该日。这限定了已查范围，仍不能推断所有历史归档及其他接口都没有记录。
- 美股晴雨表生产 ERP 历史最新为 11 月 20 日，实时接口已返回 23 日。隔离工作目录用真实三项来源生成 23 日稿成功，巴菲特指数 218.54%、ERP 5.81%，分别比较 20 日的 208.90%、6.10%。统一图片交付链输出 259,718 字节 PNG。

## 同日补充源站核对与成交额修复

前一轮只核查了原动态接口及留存归档，未继续核对金十公开收盘快讯，调查范围不足。金十原文实际存在 11 月 20 日收盘金额 14222.01 亿元。11 月 23 日原动态接口的记录只更新到北京时间 11:59，原程序也未核验其收盘时点，错误地把盘中 9163.71158132 亿元保存为该日观察；金十收盘快讯公布值为 15528.8 亿元。

现已加入同一发布者的公开收盘快讯补取。仅对必要交易日缺项或未通过收盘时点核验的行触发，核对原文与公开列表、交易日、沪深分项合计、前日金额和成交量单位。每次最多三日、每日至多六页、总计最多 45 秒，原始 JSON 与 HTML 随任务归档。金额保留原文小数位，成交量由“亿手”乘 100 转为“亿股”，原始公布值与换算关系一并存储。图片标明部分历史点采用收盘快讯公布位数，来源和精度在稿件数据中可查。原接口返回的盘中记录保留原始证据，不能进入收盘序列。不存在可信补充、原文冲突或单位不符时继续报错。

核验原文为 https://flash.jin10.com/detail/20261120150127681800 和 https://flash.jin10.com/detail/20261123150150092800 。按公布值重新计算，23 日较 20 日增加 1306.79 亿元，增长 9.19%，20 日均线约 1.62 万亿元。
