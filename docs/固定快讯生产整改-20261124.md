# 固定快讯生产整改与值班操作

本轮以 `eadb014` 为基础。程序故障优先排查，按原始响应 → 解析结果 → 数据库修订 → 工作历史 → 日期缓存 → 成稿逐层定位。缺少归因证据时保留“采集或解析未完成”“必要记录缺失”，不能据此宣布上游停更。

## 已实现的基础修复

- 快讯任务接口增加兼容字段 `failure`，包含错误码、原始失败消息、来源、缺失日期、最近数据日、可重试性与处理动作。原有 `error` 和任务状态继续可用。诊断绑定团队和任务，并核对当前错误，避免误用上次重试的错误文件。
- 必需交易日校验提供具体缺失日期。成交额原始响应含目标日期但无法解析成完整明细时，报告采集契约错误。未经原始响应核查的缺数不会自动归为“等待上游”。
- 美股晴雨表三个序列独立采集。一个序列失败时仍归档另外两个成功序列，原始数值响应及 HTTP 日期、缓存 Age、内容摘要一起归档。访客令牌响应和请求鉴权头不进入归档。ERP 和巴菲特指数分别指出缺少的目标日或前一交易日。
- HTTP 临时失败限次重试，成交额分页遵守总读取预算。意外任务异常成为可见失败并释放活动键，租约恢复连续中断六次后停止并报告。数据库不可用时继续保留租约作为恢复边界。
- worker 每分钟记录业务告警及恢复，状态文件跨重启去重。健康巡检失败独立记错，不阻止队列调度。现有登录后健康接口展示业务故障，容器探针检查 150 秒心跳。
- 发布使用服务器文件锁保护本地和 Actions 两种入口。发布镜像在复制本次代码前清除旧应用目录，防止被删除的模块残留。worker 发布时合并专用健康检查覆盖文件。

## 检查与恢复

在既有生产服务器 `/home/deploy/plus` 执行下列只读检查。

```bash
docker exec plus-api python -m app.services.production_health
docker exec plus-api python -m app.services.production_health --worker
docker compose logs --since 30m brief-worker
docker compose ps
```

完整业务检查遇到告警返回非零，心跳检查仅反映处理进程。业务报告可能同时有日历预警和出稿错误，应逐项查看。自动记录位于业务持久卷 `.brief-production-alerts.json`，错误详情在各团队的 `briefs/runs/<任务编号>/error.json`，美股来源失败列表为 `source-failures.json`，数值响应为 `us-source-*`。原始归档同时由既有工作流写入 PostgreSQL。

发生缺数时先查任务编号对应的原始响应与解析前后日期。原始响应有数而数据库无数，追查解析、事务与方法匹配。数据库有数而工作文件无数，核查历史恢复。工作文件有数而成稿无数，核查目标交易日、缓存签名与规则。原始响应缺数仍应继续查既有归档及同口径来源，保留调查范围与结论限制。

修复后通过编辑端对所需日期重新生成并核对。重绘仍使用所选稿件的不可变快照。确认和下载显式绑定版号。对于已有人工稿，重试前先核对当前版本。

发布继续使用 `deploy/deploy.sh` 或现有 Deploy PLUS 工作流。服务器新增的 `brief-worker-health.yml` 只配置 worker 探针。以后若手动重建 worker，应同时传入 `-f docker-compose.yml -f brief-worker-health.yml`。源配置、环境文件、数据库和存储卷沿用既有部署。容器 unhealthy 提供故障信号，Docker 自身不会因为该状态自动重启容器。进程退出由既有 restart 策略恢复，执行超时和租约机制负责任务恢复。

## 基础采集与恢复整改

- 增加独立于出稿的收盘采集：A股16:00后、货币市场17:15后、纽约市场当地16:15后。失败只在30分钟和60分钟后的槽位有限补试；成功即停止本轮补试。北京时间工作日07:00—08:00再检查修订。纽约时区自动处理夏令时，周五美股收盘可于北京时间周六归档。数据采集不建立稿件，也不调用文案AI，不进入两个AI算力栏目的自动出稿流程。
- 成交额原始接口继续归档；其缺少完整收盘记录时，使用东方财富日线000001/399001的f56成交量（手）和f57成交金额（元）。分别除以1,000,000与100,000,000转为亿股、亿元，Decimal保留全部原始小数。399106不兼容原深圳序列，禁止替用。补数前要求至少5个共同日期的沪深金额、成交量全部一致，超出原始精度容差即明确失败。每次最多检查两个月，原始响应、哈希、逐日来源和重叠核验报告随任务入库。交易所日度概况存在口径差异，不直接拼接。
- 真实响应回归样本验证：15个正常重叠日金额、成交量一致；2026-11-23原小程序为午盘9163.71158132亿元，独立收盘行情为15528.8017283684亿元；11月20日为14222.0042293739亿元，成交量1071.520334亿股。该周五不再视作行情源不存在记录。
- 增加数据库质量状态与原因；原始观测值、哈希和修订不被改写或删除。旧解析遗漏的更新时间通过已归档原始分页逐条匹配金额及成交量后核验，不能仅按日期把所有修订一并排除。数据导出包含质量状态与隔离原因。
- 成交额工作历史是已接受数据库观测的投影，禁止使用追加合并把隔离记录重新带回。工作JSON截断时从数据库重建并记录诊断。新生成使用恢复后的观测；重新取数仍显式访问行情；图片重绘继续使用所选版本的不可变快照。
- 进程中断的任务在重新认领前先归档已捕获响应，并把已解析的成功数据入库；后续绘图或文字失败也保留采集成果。归档与解析各自使用保存点，解析失败不能吞掉原始响应。
- 收盘采集错误立即进入业务健康告警，包含实际采集目标日期；不等到次日上午才出现。后续其他日期的成功不能清除本日期的失败。早晨出稿任务优先于后台补查。

以上代码完成不等于生产验收完成；最终镜像、迁移与九栏目在线验证必须另行记录。

## 11月25日追加：巴菲特指数数据库导出

设置 → 数据库新增“A股巴菲特指数”和“美股巴菲特指数”两个独立数据集，沿用团队权限、日期范围以及CSV/XLSX/JSON导出。每个数据日、来源方法取已接受观测的最新修订，原始各次修订仍在“快讯数据历史与修订”。来源方法不同的同日记录分别保留，不擅自合并。

导出提供指数百分数、比值、市值分子、GDP分母、单位、GDP期间及版本说明、来源、修订号、证据ID和采集时间。历史记录未保存GDP输入或版本时留空并说明，不补造。A股当次更新的每个日期按自身年份选择全年GDP，保留所用发布版本；美股保留Wilshire与FRED季度年化GDP输入，明确当前修订序列不等于历史当时可得版本。美股历史可以从数据库现存输入计算入库，导出请求本身不联网抓取。

追加核验发现美股旧实现将Wilshire点位当美元市值，属于程序语义错误，先前218.54%的成功只证明流程能跑通，不能证明精确市值口径成立。已建立共享数量/单位契约，A股计算及导出共用同一比值函数；生产、确认、业务健康共用同一契约判断。旧的美股代理计算单独标为未核验历史，保留点位单位及质量原因，不伪装真实美元市值。真实市值输入未接通前，不生成或确认精确美股巴菲特稿。MacroMicro、GuruFocus普通程序请求本次返回403，未绕过访问限制，也不以外部访问问题解释旧代码的单位错误。

## 根因与长期约束

| 已证实根因 | 基础修复 | 防回归证据 |
|---|---|---|
| 同一数值字段缺少数量含义、单位与收盘状态约束 | 共享数量契约；行情来源、质量状态和逐日时点入库 | 指数点冒充美元、币种混用、无效数字均拒绝 |
| 追加历史把被剔除值重新合并回来 | 数据库保留原始修订；工作文件仅投影已接受记录 | 旧快讯、盘中值、损坏文件恢复后均不能复活 |
| 采集成果依附后续出稿成功，进程中断可丢成果 | 独立收盘任务；认领中断任务前持久化部分成果 | 任务重复认领、后续失败不丢成功数据且不重复写入 |
| 测试数字复现被当成来源语义成立 | 真实响应回放、独立重叠日核验、单位反例及真实PG迁移 | 样例相符仍不得越过数量维度契约 |

长期连续生产观察尚未完成；美股真实市值口径也未闭环，不能宣称九栏目已全部达到商用交付条件。

发布可靠性：服务器日志实际记录过MaxStartups限流丢弃认证前连接，不能将SSH中断一概归为密钥失效，也不能据此解释快讯应用自身故障。发布改为服务器独立任务，状态与日志在`/home/deploy/plus/releases/dispatch/<commit>.exit|pid|log`；本地和Actions共用同一启动/查询脚本，SSH掉线不取消远端任务。原发布锁、容器保护、迁移校验及无备份/无自动回滚约束继续生效。状态是interrupted时需核对日志与实际服务，不自动重启未知阶段的发布。
