# 数据补抓与长期存储（2026-10-30）

本次修复覆盖全部 9 个固定快讯的数据链路。目标是从真实来源补回缺失记录，并持续保存已经取得的数据。源站没有提供的历史记录仍需取得真实资料，不能靠插值、沿用旧值或替换成其他指数制造完整性。本次代码未部署，也未连接或迁移生产数据库。

## 长期数据库

增量迁移 `0018` 新增两个表，并为 `brief_configs` 增加独立的 `data_enabled` 开关。升级时继承原团队的自动任务开关，不自动开启原已关闭团队的采集。

- `brief_data_points`：按团队、栏目、序列、来源方法、数据日期和修订号保存结构化数值、单位、内容哈希、任务、来源快照和实际采集时间。历史更正新增修订，不覆盖旧值。数据库记录独立于工作缓存和稿件版本清理。
- `brief_data_checks`：保存每次任务的覆盖区间、缺失日期、来源差异和恢复情况。

两个表均已接入「设置 → 数据库」按时间范围导出，继续执行团队隔离；不导出密钥、密码哈希或原始网页、来源二进制。历史序列 API 为 `GET /api/briefs/data-series`，参数包括 `category`、`series`、`start`、`end`、`as_of` 和 `limit`。`as_of` 必须带时区，表示本系统实际取得证据的时间，不代表事后下载的数据在历史日期已经可得。返回 `truncated=true` 时应缩小查询区间。

不同来源方法分别保存，不把来源切换后的序列伪装成同口径历史。旧证据迟到入库时，不应覆盖采集时间更晚的当前版本。

## 补抓与内容生成分离

「持续采集、补齐并保存数据」可独立于自动制稿启用。10 点以后按 6 小时周期安排补抓，覆盖当前 9 栏和有限的历史任务；每团队每周期最多 18 个任务，避免积压占满服务器。补抓不调用文案模型，不创建或覆盖编辑稿、确认稿。

Token/GPU 继续手动生成内容；后台可采集数据，不加入自动晨间制稿。部分来源失败时，已经取得的真实数据先保留，不能因为图片、其他指标或派生值失败而丢弃全部输入。换手率均线遇到真实缺失交易日时不跨缺口计算。

成交额改为分页获取并合并增长历史；换手率保存原始计数历史；DR 可从官方逐日历史补回已经离开实时报价页的收盘加权利率；美股指数按真实日期区间补抓并校对重叠数值。ERP 仅在当日 PE、指数收盘和国债收益率三个真实输入齐全时回算。每日 PE 明细单独留存，避免长历史接口的周度抽样丢失已经发布的日数据。全 A 总市值也独立保存，不因 GDP 分母或指数来源缺失而丢弃。

交易日历区分上交所、银行间市场和纽约证券交易所；银行间调休工作日不套用股票交易日。当前上交所日历覆盖到 2026 年底，银行间日历为 2026 年；超范围明确报错，下一年度必须更新正式日历。未对未知年份按普通工作日猜测。

## 迁移与旧资料入库

部署前备份现有数据库与存储，在与生产同版本的副本验证迁移。迁移 `0018` 不替换旧库；此次未执行生产迁移。完整旧迁移链的离线 SQL 生成会在既有 `0013` 数据回填处失败，单独生成 `0017:0018` 的 SQL 可用，不能把离线全链生成当成已经验证通过。

升级到 `0018` 后，可按明确团队恢复已归档资料。以下命令默认回滚数据库写入，仅在新的报告目录输出结果；加入 `--apply` 才会提交恢复数据并重建该团队的工作历史。工具不生成稿件。

```powershell
python -m app.briefs.repair --team-id TEAM_UUID --out NEW_REPORT_DIRECTORY --issue-date 2026-10-30
python -m app.briefs.repair --team-id TEAM_UUID --out ANOTHER_NEW_DIRECTORY --issue-date 2026-10-30 --apply
```

迁移本身不自动解析所有旧快照。正式补齐仍需运行上述恢复、启用独立采集，并按剩余日期取得真实缺失来源。长期可恢复还依赖数据库及原始证据的定期备份；本次没有配置生产备份或证明灾难恢复能力。
