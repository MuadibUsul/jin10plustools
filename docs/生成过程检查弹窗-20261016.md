# 生成过程检查弹窗（2026-10-16）

## 需求

- “生成过程”点击后要能核对本次生成的真实计算说明：数据从哪来、原始指标是什么、怎么计算、图表与文案如何组成最终结果；面向检查用途，低频使用。
- 做成可复用组件：后续新增快讯产品接入同一套记录机制后，自动获得同样的查看入口，API 与前端不需要为单个产品改动。

## 交互

- 独立弹窗，点击卡片上的“生成过程”按钮才动态加载 `/generation-process.js` 并读取本次任务；弹窗内提供“刷新记录”手动刷新，不做轮询，不增加常驻面板。
- 弹窗分七块：本次执行方式（是否复用快照/重新取数/重新制图/补跑AI）、执行记录（真实阶段事件，含来源与计算核对行）、数据从哪里来（来源名称与外链）、本期输入与计算结果、如何计算（含代入本期数值的公式行）、如何组成最终结果（规则标题、正文、配图、DeepSeek状态与警告）、原始证据（已登记快照的文件名、字节数、行数、SHA-256，附最后两条样例记录与原始指标字段）。
- 复用旧快照时明确显示“复用已有同日期快照，本次未重新取数”，避免误认为重新取数；未保存完整结果时只展示处理规则与执行记录。

## 实现

- 后端 `GET /api/briefs/jobs/{id}/process`：仅编辑与管理员可读，viewer 返回403；只允许本团队任务。返回 `{job, details}`。
- `app/briefs/process_details.py`：从运行目录读取已登记的结果与快照，生成来源、代入数值的计算说明、输入值与证据哈希。只接受固定登记的文件名，不接受用户路径，不遍历目录；来源URL去除签名参数，敏感字段（key/token/secret/password等）不输出；不返回引擎日志。
- 适配器可通过结果 payload 的 `process_details` 提供自有来源/公式/输入；`runner.py` 在制图阶段把来源与计算核对写入执行记录，弹窗按记录机制读取，新产品无需改API或组件。
- 前端 `app/web/generation-process.js`（共享组件，`showGenerationProcess({title, load})`）与 `generation-process.css`；`briefs.js` 在“生成过程”按钮上按需调用。

## 验证

- 后端 `tests/test_process_details.py` 4项与全套145项通过（含viewer 403、跨团队404、无结果与复用路径）。
- 前端 `tests/generationProcess.test.ts` 4项与全套68项通过；typecheck、lint通过。
- 本地真实浏览器实测：打开七个区块、代入公式行（“本期成交额：24138 ÷ 10000 = 2.41 万亿元”）、来源外链、SHA-256、成稿配图、样例记录、执行记录中文时间（“2026年10月16日 9:22”）；“刷新记录”重载正常；“关闭”正常；换手率复用样例显示复用提示与“DeepSeek：调用失败，保留规则稿”。
